## Реализация плана

- **P2-2 реализован:** общий validator внешнего source SELECT использует граф
  FROM SQLAlchemy без emission warning; фильтры предупреждений его не отключают.
  Проверка выполняется перед INSERT в общем пути и после преобразований
  ClickHouse-hook. Поддержаны linked JOIN, IN/EXISTS, корреляция, aliases,
  одинаковые имена в разных схемах, FINAL источника ReplacingMergeTree.
  Тексты ошибок не включают SQL, значения фильтра или URL.
  Тесты: `/SSD/Projects/dbmerge/tests/test_source_condition.py`.
- **P2-1 реализован:** отсутствие watermark вызывает первый rebuild без
  change-записей; обработка пустого источника, retry после ошибки и последующий
  idle/restart проверены. Safe boundary, lease и post-acquire перепроверка
  состояния сохранены. Источники должны быть готовы до включения цикла.
- **P3-1 реализован:** конструктор MartLoop идемпотентно регистрирует logical
  destination через tracker engine/service schema; кэш таблицы не сбрасывается.
  Disabled/stop не запускают расчёт. Flag/token/cursor/boundary/watermark
  сохраняются; при ошибке закрывается только owned lease, borrowed не закрывается.
  Цикл публикуется в weak registry только после успешной регистрации.
- На PostgreSQL тест с двумя subprocess одновременно создаёт отсутствующие
  служебные таблицы/строку витрины и запускает первый проход: один callback,
  одна строка состояния и сохранённый watermark. Проверка использует заранее
  созданную изолированную схему, то есть не доказывает гонку CREATE SCHEMA.
- **P3-2:** неанглийские собственные runtime-шаблоны не обнаружены. Добавлена
  узкая AST-регрессия кириллицы в literal logging/print/raise шаблонах; это не
  проверка пользовательского вывода на ASCII и не распознавание всех языков.
- Обновлены руководства, README, llms.txt, runner example и changelog; новые
  source-тесты включены в Python и ClickHouse workflows. PostgreSQL concurrency
  и новые mart-тесты уже входят в явные серверные CI-команды.

## План реализации и критерии приёмки

### 1. P2-2 — защита source SELECT, отдельный патч

Начать с регрессионных тестов общего SQL-пути и ClickHouse hook. Проверить
target с 0/1/несколькими строками, несколько периодов source, одинаковые имена
в разных схемах. Ошибочный target-фильтр должен давать `IncorrectParameter`
до INSERT staging и DML назначения, даже если SQLAlchemy warning отключён.
Создание staging в конструкторе — отдельный DDL side effect, не обещать его
отсутствия при проверке в `exec`.

Проектировать общую проверку верхнеуровневого FROM и связности SELECT, а не
запрет всех чужих Column. Сохранить корректные IN-subquery, EXISTS, алиасы,
коррелированные подзапросы и явно связанные JOIN. Проверку применять и после
ClickHouse-преобразований условий, не допуская расхождения двух SQL-путей.
Не подменять target-колонки source-колонками автоматически. Не вводить новый
opt-out до определения поддерживаемого контракта намеренного CROSS JOIN.

Приёмка: тесты раннего отказа и допустимых запросов; live ClickHouse сравнивает
`total_row_count`, staging count до cleanup и query_log по конкретному query ID.
Отсутствие прав query_log — явный skip, не успех. Materialized views отдельно.
**Не менять арифметику row count без отдельного воспроизведения.**

### 2. P2-1 — первоначальная инициализация витрины

В `/SSD/Projects/dbmerge/src/dbmerge/mart.py` ограничить проверки продвижения
границы и source-changes обычным инкрементом (`not full_rebuild`). Сохранить
safe boundary, lease acquisition, перепроверку состояния после acquisition,
request token, resume cursor, guarded commit прогресса и cleanup.

Тесты: заполненный источник вне журнала; пустой источник; ошибка первого
расчёта и retry; второй no-op проход; последующий инкремент; disabled/stop;
resume/explicit request без сигналов; новый request во время rebuild; два
конкурирующих процесса. Ошибка или отсутствие источника не фиксируют watermark.
Конструктор не выполняет пользовательский расчёт.

### 3. P3-1 — идемпотентная регистрация MartLoop

После validation/нормализации identity подготовить таблицу и строку через
`tracker.engine` в служебной схеме. Инициализировать `_marts_table` до
регистрации и не сбрасывать кэш в конце конструктора. Публиковать цикл в
`_all_loops` только после успешной инициализации; при ошибке закрывать только
принадлежащие циклу ресурсы, не borrowed lease handle.

Тесты: повторная и конкурентная регистрация; сохранение flag/token/cursor/
boundary; disabled; различие служебной и бизнес-схем; логическое назначение
без физической таблицы; существующий watermark без строки marts; ошибка
конструктора и освобождение ресурсов. Сам MartHandler без loop регистрировать
необязательно — явно описать контракт. Не создавать rebuild request при рестарте.

### 4. P3-2 — runtime-диагностика

Инвентаризировать собственные logging/warning/exception/print шаблоны библиотеки
и примеров; исправлять только реально найденные неанглийские шаблоны. Добавить
узкие AST/поведенческие проверки ключевых диагностик. Не проверять весь
отформатированный лог на ASCII: пользовательские данные и внешние ошибки
могут содержать любой язык.
