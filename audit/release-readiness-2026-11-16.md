## Область и заключение

Аудит рабочего дерева после подготовки канонического имени `DBMerge`.
Метаданные проекта пока остаются **2.5.0**, изменения относятся к **Unreleased**.
Коммиты, push, смена версии и публикация не выполнялись. Предыдущие изменения
переименования сохранены. Это инженерный аудит с локальными воспроизведениями,
а не независимая сертификация или доказательство отсутствия дефектов.

**Заключение:** найдены и исправлены дефекты lease-идентичности, конкурентного
старта, валидации фоновых интервалов, примера shutdown и поставки документации.
Локальные проверки зелёные. Разрешение на релиз по всем СУБД пока дать нельзя:
нужен серверный CI на окончательном diff, особенно tracking/marts и DDL гонки.

## Методика

- Просмотр публичного API, конструктора/exec/cleanup, generic SQL flow,
  tracking completion/recovery, lease acquisition/renewal/tokens, mart watermark
  и rebuild state; выборочный просмотр bulk/chunks и dialect hooks.
- Сопоставление сигнатуры с API-документацией; проверка Python-блоков основных
  руководств, локальных файловых ссылок, runnable SQLite-примеров.
- Просмотр package metadata, sdist allowlist и явных команд pytest в CI.
- Регрессионные тесты подтверждённых проблем, отдельный merge-прогон SQLite.
- Сборка sdist и wheel из sdist, проверка метаданных twine, compilation и whitespace.

Не все ветви каждого dialect module изучены построчно. Новая матрица серверов,
профилирование всех backend loaders, coverage/fuzzing, проверка CVE, внешних
ссылок и визуальной доступности rendered Markdown не выполнялись.

## Документация: оценка

### Сильные стороны

- Подробно объяснены полное/частичное удаление, пустой snapshot, уникальность
  ключей, вывод типов и per-step commits. Не скрыты сознательные опасные defaults.
- Есть отдельные Oracle/ClickHouse ограничения и compatibility matrix.
- Tracking/marts обозначены beta; описаны отдельность data/journal commits,
  borrowed handles, scope и ограничения cross-engine fencing.

### Что улучшено

- Первый пример исполним без сервера и optional DataFrame библиотек, с понятным результатом.
- Объяснено, что опубликованная 2.5.0 ещё не экспортирует `DBMerge`;
  дан совместимый import. Package name и logger не меняются.
- Добавлены выбор руководства по задаче и воспроизводимые команды проверок.
- Автоматизированы синтаксис Python-блоков, локальные файловые ссылки, полнота
  списка параметров, исполнение quick_start/user_guide, optional-import isolation.

### Оставшиеся улучшения, не блокирующие merge API

- Основная документация англоязычна; полного русского quick start и API guide нет.
  Нельзя считать доступность для русскоязычного новичка максимальной.
- Документация — крупные Markdown-файлы, без полноценного сайта с поиском и
  версионированием. Сайт можно спланировать отдельно; новый framework не добавлялся.
- Часть snippets — фрагменты с заранее определёнными engine/data/ctx.
  Синтаксическая проверка не доказывает их runtime-корректность на сервере.
- Проверяются файловые ссылки, но не remote URLs и не anchor fragments.
- Заявления compatibility/performance — исторические результаты проекта,
  а не повторные измерения этого аудита. Нужны дата/окружение для новых замеров.
- Короткие server-dependent scripts местами намеренно полагаются на завершение
  процесса для cleanup; это объяснено, но не образец для встраивания в сервис.

## Риски и решения перед релизом

1. **Обязательно:** CI по PostgreSQL/CockroachDB/MySQL/MariaDB/SQL Server/Oracle/
   ClickHouse/DuckDB на конечном diff; особенно конкурентные PG-тесты.
2. DDL race регрессия локально детерминированно имитирует устаревший inspect;
   не равна live multiprocess проверке схем на каждом сервере.
3. Defaults не менялись: `delete_mode='delete'` с пустым snapshot удаляет всё
   в scope; `commit_all_steps=True` допускает частичный результат; DDL не входит
   в атомарную транзакцию данных. Сохранены warnings/checklists.
4. Конкурентные rebuild/changes, cross-engine journal, version ties ClickHouse
   остаются ограничениями модели, а не устранёнными аудиторскими дефектами.
5. `can_create_columns=False` пропускает отсутствующие обычные поля с warning,
   это не strict schema-validation режим. Не интерпретировать его как запрет потери
   неизвестных полей без дополнительной проверки на уровне вызывающего кода.
6. Локальный merge performance имеет медленные source-table scoped-delete случаи
   (до 86 s). Это наблюдение теста, не регрессия, измеренная относительно baseline.
7. Перед публикацией выбрать новую версию, обновить lock/metadata и version notes,
   changelog, установить финальный wheel в чистое окружение. `DBMerge.__name__`
   меняется; строковая проверка старого имени не совместима, alias совместим.
8. Только после публикации совместимой зависимости обновлять onecdc. Его код,
   зависимости и публикации в этом аудите не затрагивались.
